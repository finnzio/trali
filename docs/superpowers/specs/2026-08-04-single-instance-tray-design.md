# Windows 托盘重复实例修复设计

## 背景

当应用设置为关闭到系统托盘后，主窗口会被隐藏但进程仍然运行。当前启动链路没有单实例互斥，也没有处理第二次启动事件，因此用户从 Windows 桌面或开始菜单快捷方式再次打开应用时，会创建第二个进程和第二个托盘图标。

## 目标

- 整个桌面应用只运行一个实例。
- 已有实例隐藏到托盘时，再次从快捷方式启动应恢复并聚焦已有主窗口。
- 已有实例可见时，再次启动只聚焦已有主窗口。
- 通过托盘退出后，下一次快捷方式启动仍可正常创建实例。
- 不改变现有托盘菜单、关闭行为、全局快捷键和移动端入口。

## 方案

引入 Tauri 官方 `tauri-plugin-single-instance`，并将其作为第一个桌面插件注册。插件在发现已有实例后阻止新实例继续运行，并把第二次启动交给已有实例的回调。

第二次启动回调复用一个独立的主窗口恢复函数：先取消最小化，再显示窗口，最后设置焦点。托盘“显示”菜单和第二次启动回调都调用这个函数，确保两个入口拥有相同的行为。

依赖仅在桌面平台启用，注册使用 `#[cfg(desktop)]`，保持移动端构建路径不变。回调不需要处理启动参数，因为当前快捷方式没有承载需要转发的文件或 URL。

## 数据流

```text
快捷方式启动
    |
    v
单实例插件检查
    |-- 无已有实例 --> 正常创建应用、托盘和主窗口
    |
    `-- 已有实例 --> 调用已有实例回调
                          |
                          v
                 取消最小化 -> 显示 -> 聚焦
                          |
                          v
                    新进程退出
```

## 错误处理

- 主窗口不存在时，恢复函数返回已有的可读错误；托盘事件和单实例回调继续采用当前“忽略单次 UI 操作错误”的策略，不让辅助入口使应用崩溃。
- 单实例插件初始化失败时，沿用 Tauri setup 的错误传播，让应用启动失败并暴露配置问题，而不是静默允许多实例运行。
- 不新增自定义互斥体、IPC 通道或 Windows 专用资源，避免额外的清理和跨平台分支。

## 测试与验收

1. 添加一个针对窗口恢复入口的 Rust 回归测试，验证第二次启动使用与托盘“显示”相同的恢复路径；先确认测试在实现前因缺少该路径而失败。
2. 运行针对 Rust 代码的格式检查和测试。
3. 运行前端构建，确认 Tauri 依赖变更没有破坏跨边界类型或打包前端。
4. 在 Windows 安装包中手动验收：隐藏到托盘后启动桌面快捷方式，托盘图标数量保持为一个且主窗口恢复并获得焦点；重复启动和托盘退出场景按目标验证。

## 范围与非目标

本次只处理应用启动时的重复实例问题，不修改启动参数协议、不处理文件/URL 转发，也不重构已有托盘状态管理。
